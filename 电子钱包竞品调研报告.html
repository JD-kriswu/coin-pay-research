1. 执行摘要

市场已从"硬件 vs 软件"的二选一走向融合:硬件厂(OneKey、Tangem)主动叠加 keyless/托管恢复层,软件厂(币安、Zengo)用 MPC 把"无助记词、可找回"做成大众标配。对我们"面向大众 + 企业"的双定位,单押一派都不够——大众要"丢了能找回"的容错,企业要"信任最小化 + 多签/门限"的自主。最值得走的范式是「硬件安全底座 + 可选托管/MPC 恢复层」的混合架构。而企业/B 端方案是全行业集体空档(仅 Ledger 有 Enterprise),是最该重点打的差异化。

五个最关键的发现

  • 丢失恢复是真正的分水岭。纯硬件派(Tangem)"全卡丢光 + 没设助记词 = 永久归零";keyless 派(Zengo/币安)扫脸/邮箱/云几秒找回,但要信厂商服务器。两派在防不同的威胁。
  • Tangem 的多卡备份有硬伤(见目标一评审):激活后不能补卡、改密码不能作废丢失的旧卡——冗余买定离手,这是可以甩开它的点。
  • 恢复方案百花齐放:Ledger Recover(2/3 Shamir 分片 + 三国 HSM + KYC)、Trezor Shamir 门限、Zengo 律所托管 + GitHub 自救、OneKey Lite NFC 卡 / Keyless、币安 MPC 3 片。可借鉴的成熟范式很多。
  • App 信息架构在收敛:各家都把高频交易动作(买/卖/Swap/Earn)前置到一级导航,把恢复/备份沉到独立专题。币安"同一入口切 CeFi⇄DeFi + 无感互转"最值得学。
  • 功能在"超钱包化":OneKey 已把 Swap/法币/DeFi/现货/永续合约全塞进 App;Tangem 做了 Tangem Pay 虚拟 Visa 卡。钱包正长成"Web3 金融入口"。

3. 专题一:丢失恢复 · 硬件派 vs keyless 派安全对比

这是本次调研的核心关切,也是自家方案最关键的分叉。结论:不是"谁绝对更安全",而是两派在防不同威胁、把信任交给不同对象。

先破一个误解:keyless 不等于"没有私钥"。私钥一直存在,只是形态变了。硬件派把完整私钥锁在离线芯片、永不触网;keyless 派(MPC)把私钥拆成 2~3 个 share 分布在设备/服务器/云,签名时在线协同计算、全程不拼出完整私钥。两派都"有私钥",区别在下面。

3.1 各自防什么、怕什么

维度硬件派(Ledger/Trezor/Tangem/Keystone)keyless/MPC 派(币安/Zengo/OneKey Keyless)
私钥是否触网否,锁离线芯片是,share 在联网环境协同签名
最强防线物理隔离——远程黑客/恶意软件够不着私钥无单点——偷一个 share 没用,要同时攻破 2 处
最怕什么设备丢失/损坏 + 物理接触 + 助记词被偷服务器被攻破/作恶、MPC 实现有后门、云备份被撞库
信任交给谁只信自己(私钥全在你手上)信厂商服务器 + 它的 MPC 实现没问题
可验证性可完全离线、开源可审计(Trezor/Keystone)普通人无法验证服务器端那片 share 怎么处理
丢失恢复难——靠助记词/分片/多卡自己扛(Tangem 全丢归零)易——扫脸/邮箱/云一拉就回(Zengo 几秒)

本质:硬件派押"物理隔离 + 自我保管"——够不着,但你自己得扛住保管和丢失;keyless 派押"密码学门限 + 厂商协同"——方便恢复,但你得信那个服务器。

3.2 分场景:谁更安全(别笼统答)

  • 防远程大规模攻击:两派都不错(硬件靠离线,MPC 靠多方)。
  • 防厂商作恶/服务器被攻破:硬件派明显更强——你的私钥压根不在厂商那儿;MPC 派这里是软肋。
  • 防用户自己犯错(丢设备/丢助记词/记不住):keyless 派明显更强——这正是它的立身之本;硬件派最脆(Tangem 全卡丢 + 没设助记词 = 永久归零)。
  • 防胁迫/物理抢夺:打平——硬件有诱饵钱包/passphrase(Keystone/OneKey),MPC 有生物识别锁 + 提现限额(Zengo Pro)。
结论:"谁更安全"取决于你最怕哪种威胁。高净值老手怕厂商和黑客 → 选硬件;大众新手怕自己把钱弄丢 → 选 keyless。

3.3 为什么有的选硬件、有的选无硬件 —— 本质是"安全自主权 vs 易用容错"的取舍

选硬件 服务"信任最小化"诉求

  • 用户:高净值、长期持有、老手
  • 诉求:"除了我自己谁都动不了,也查不到"
  • 愿承担保管成本(记助记词、保管设备、学习门槛)
  • 怕:交易所暴雷、厂商跑路、政府传票、远程黑客
  • 代表:Ledger / Trezor / Tangem / Keystone

选无硬件 服务"大众可用性"诉求

  • 用户:新手、小额、把钱包当 App 用
  • 诉求:"别让我记 24 个单词、换手机别丢钱"
  • 硬件那套"抄助记词、丢了就没"对大众是劝退点甚至资产流失主因
  • 愿用"信任厂商一部分"换"像 Web2 能找回账号"
  • 代表:币安 Web3 / Zengo;OneKey 用 Keyless Wallet 兼容
关键:市场不是二选一,而是在融合(调研实锤)。OneKey(硬件厂)自己加了 Keyless Wallet;Tangem(硬件厂)把助记词做成可选、并上线 Tangem Pay 支付账户;各家都在"硬件安全底座"上叠"软件易用恢复层"。

3.4 各家丢失恢复方案一览(可借鉴的成熟范式)

3.5 对自家"面向大众 + 企业"的含义(建议):大众和企业的取舍恰好相反——大众要 keyless 的容错,企业要硬件的自主。单押一派都不够,应走"硬件安全底座 + 可选托管/MPC 恢复层"的混合架构:极致自主用户用纯硬件 + 自管分片;怕丢的大众开启托管恢复层(类 Ledger Recover 或 Zengo 自救);企业用多签/门限(类 Trezor Shamir 分组)+ 可审计。而企业方案是集体空档(仅 Ledger Enterprise),是最该重点打的差异化,不要在个人消费硬件上和 Tangem/OneKey 拼价格拼功能。

4. 专题二:多钱包诉求 → 各家实现

从"用户为什么要多个钱包"的真实诉求出发,逐一拆解 7 家怎么实现,最后落到对自家的分层设计启示。部分厂商细节标注"待核实"(官方资料未找到可靠来源,不臆断)。

4.1 用户为什么要多钱包(6 类场景,按诉求强弱)

#场景说明典型代表
1资金分层(最高频)日常小额用热钱包、长期大额进冷钱包。热钱包持续联网钓鱼暴露面大,大额值得独立钱包而非同一钱包下的独立账户Tangem 讲得最透
2用途隔离 / 记账清晰储蓄、交易、某 DeFi 项目各一账户贴标签——"带标签的隔间",图条理清楚,非安全隔离各家通用
3链上隐私 / 防关联不同账户用不同地址,降低链上追踪Zengo Privacy Mode
4多实体 / 多人分账(企业刚需)个人 vs 团队 vs 公司分开,企业按角色分权Zengo Business / OneKey 团队钱包
5风险实验隔离独立种子钱包碰高风险 DeFi、撸空投,被盗不波及主资产各家通用
6胁迫防护(plausible deniability)passphrase 隐藏钱包,受胁迫只交诱饵钱包Trezor/Keystone/Ledger/OneKey 都主打

4.2 两种实现形态(关键分野,Tangem 讲得最清楚)

① 多账户 = 同一套私钥 HD 派生:一份助记词(或一组卡)全恢复,成本低;但只是"逻辑隔间"不是安全边界,链上可能被关联。

② 多套独立钱包 = 各自独立私钥:一个被攻破不波及其他,真隔离 + 支持胁迫防护;代价是每套单独备份、恢复成本翻倍。

多数用户最终是混合用法。这个分野直接决定备份恢复复杂度,必须和丢失恢复方案一起设计(呼应专题一:冗余不可后补)。

4.4 逐家要点(谁适合什么)

  • Keystone(硬件端最彻底):一台设备管最多 3 套完全独立助记词(各用不同密码),每套之上还能叠多个 passphrase 隐藏钱包,支持 Shamir 分片;可接 Gnosis Safe 做多签签名器(非多签平台本身)。
  • OneKey(整合体验最好):同一 App 管多个独立钱包(软件/硬件/Keyless),可命名加头像区分个人/团队;独有 Attach to PIN——不同 PIN 绑不同 passphrase,快速切换多隐藏钱包免手输。
  • Zengo(企业分账最佳样板):多钱包是"独立实体可各附不同安全策略"(MPC 下各自独立份额);Zengo Business 在 seedless 下做多用户治理,角色分 Admin/Approver/Controller/Viewer,邮件邀请分配撤销——企业多实体分账的现成范式。
  • Ledger / Trezor / 币安种子钱包(HD 派生派):胜在"一份助记词全恢复"低成本;passphrase 是隐藏钱包主力(Ledger 可 attach PIN、Trezor 每次手输主打 deniability),但 passphrase 丢了永久丢。
  • Tangem:单钱包 ≤20 account(同主种子 HD 派生),同时 App 内可管无限个独立钱包(每个对应自己一组卡,真多套独立私钥);无企业多签方案。
4.5 对自家的启示(分层设计):
  • 大众层:默认"一套密钥 HD 派生多账户 + 一份备份全恢复"保易用(学 Tangem/币安:20 账户上限 + 账户列表切换)。
  • 进阶 / 高净值层:提供"一机多套独立种子 + passphrase + Attach-to-PIN"做真隔离与胁迫防护(学 Keystone + OneKey)。
  • 企业层:单独做"MPC + 多角色审批(Admin/Approver/Controller/Viewer)+ 可对接 Gnosis Safe 多签"治理线(学 Zengo Business),不要用消费级 passphrase DIY 硬撑企业分权。

待核实:Tangem/币安导入钱包 passphrase 支持、Ledger 企业线、Keystone 多种子切换 UI、Zengo 多钱包恢复粒度、OneKey 企业治理。

5. 自家钱包功能基线建议

基于 7 家对标,按"必做基线 / 差异化 / 暂不做"给出。均为建议,非结论,需结合产品定位与资源再定优先级。前提:面向海外/合规市场的大众 + 企业用户。

功能说明对标参考

7.2 差异化重点(甩开竞品的地方)

  • ① 混合恢复架构(最核心):硬件安全底座 + 可选托管/MPC 恢复层。大众开启"丢了能找回"的容错(类 Ledger Recover / Zengo 自救),老手用纯硬件自管。直接解决你最关切的"设备丢失怎么办",且避开 Tangem"全丢归零"的硬伤。
  • ② 企业/B 端方案(集体空档):多签、团队钱包、多实体/多项目分账、权限与审计。除 Ledger Enterprise 外几乎无人做,是最该重点打的方向。
  • ③ 可后补的备份:Tangem 冗余"买定离手、丢一张不能补"是硬伤。若支持激活后追加/替换备份因子,是明确体验优势(需评估安全模型)。
  • ④ 面向支付的延伸:Tangem Pay(虚拟 Visa + 稳定币消费)已验证钱包往支付走的路径,契合稳定币定位。

7.3 暂不做 / 审慎(别盲目堆)

  • 全资产交易堆料:OneKey 把现货/永续合约/美股关联塞进 App,带来合规与认知门槛。面向大众 + 企业未必需要,别正面拼。
  • 纯 air-gapped 二维码:Keystone 那套每笔来回扫码,体验繁琐,大众场景不友好。
  • 语言/中文:不面向中国大陆,中文不是卖点也不是竞品短板(已确认前提)。
一个必须提前定的设计分叉:多钱包用"多账户(一套私钥派生)"还是"多套独立私钥"实现,直接决定备份恢复复杂度——结合目标一发现(冗余不可后补),若走多套独立私钥,丢失恢复成本会成倍放大。多钱包能力和丢失恢复方案是强耦合的,必须一起设计。详见第 4 节。

6. 帮助文档体系对比

关注点:怎么组织文档、有没有把"丢失/备份/恢复"做成独立专题(而非散落 FAQ)、分层逻辑。

产品组织逻辑恢复/备份专题亮点
Tangem混合:入门/安全按用户旅程,Pay/Services 按产品线有,Security 下独立 "How Backup Works" + "Device Loss & Recovery" 两篇多语言;恢复单列成专题不散落
Ledger双体系:Support(排障操作)+ Academy(科普获客),多轴(产品×旅程×难度)有,Ledger Recover 独立专题 + 设备丢失被盗专题"怎么操作"和"为什么安全"分站运营
Trezor双体系:Guides(how-to)+ Learn(what/why)有,Guides 下独立 "Backups & recovery" 一级栏目(SLIP39 + Shamir)恢复专题颗粒度细(含门限方案)
OneKey混合:设备按型号 + App 按功能 + 独立备份/排障专题有,独立"备份与恢复"专题(Lite/KeyTag/Keyless 自成体系)多种备份介质各有文档
Keystone混合:产品维度为主干 + 用户身份辅助入口分散在 Recovery Phrase / Security Practices / Self-Destruct 几页按用户身份(新手/BTCer/Web3)导航
币安 Web3三层按用户意图:Academy(是什么)+ FAQ(怎么做)+ 博客(有什么新)有,围绕"无种子短语"的专题簇(备份三法 + 恢复 + MPC)按意图分层而非按功能堆
Zengo文档体系补充调研未回,待补
共性启示:所有家都把"丢失/备份/恢复"做成独立且显眼的专题,不混在普通 FAQ 里。头部厂商(Ledger/Trezor)还把文档拆成"排障操作"和"科普获客"双体系。自家应照此:操作文档与教育内容分开,恢复/丢失预留独立专题位。

产品一级导航(主模块)IA 特征
